# 🚀 Инструкция: как запустить бота по шагам

У тебя на руках две части:

1. **Чат-бот (папка `src/`, Python)** — полностью рабочий. Дайджесты + вопросы к
   библиотеке прямо в чате Telegram. **Это можно запускать уже сегодня.**
2. **Mini App (`miniapp/MNTKMiniApp.jsx`)** — готовый прототип интерфейса (дизайн и UX).
   Чтобы стать «настоящим» Mini App, нужен ещё один этап разработки (см. ЭТАП 2).

> **Главный совет:** запускай ЭТАП 1 сейчас. Это законченный полезный продукт для врачей.
> Собери первых пользователей из МНТК, проверь, что заходит. Красивый Mini App (ЭТАП 2)
> делай вторым шагом — когда подтвердишь спрос. Так не потратишь время на обёртку раньше времени.

## ЭТАП 1 — Запустить чат-бота (можно сегодня)

### Шаг 1. Создать бота в Telegram
1. Открой в Telegram **@BotFather**.
2. Отправь `/newbot`, придумай имя и username (заканчивается на `bot`).
3. Скопируй **токен** (длинная строка вида `12345:AAH...`).

### Шаг 2. Получить ключ OpenAI
1. Зайди на **platform.openai.com** → API keys → Create new secret key.
2. Скопируй ключ (показывается один раз).
3. Пополни баланс на несколько долларов (бот тратит токены на сводки и ответы).

### Шаг 3. Подготовить проект
1. Распакуй архив.
2. Установи **Python 3.11+** (python.org), если ещё нет.
3. В папке проекта скопируй `.env.example` → `.env` и впиши:
   - `TELEGRAM_BOT_TOKEN=` — токен из шага 1
   - `OPENAI_API_KEY=` — ключ из шага 2
   - `NCBI_EMAIL=` — свой email (нужен PubMed/Crossref для нормального лимита)

### Шаг 4. Запустить
В терминале, в папке проекта:
```bash
pip install -r requirements.txt
python -m src.bot
```
Бот запустится. Не закрывай терминал, пока он работает.

### Шаг 5. Проверить
В Telegram открой своего бота:
- `/start` — приветствие
- `/digest` — соберёт свежие проверенные статьи (~1–2 мин) и пришлёт топ
- напиши любой вопрос текстом — получишь ответ со ссылками на источники
- `/saved` — сохранённые статьи (жми «Сохранить» под карточкой)

### Шаг 6. Авто-дайджест в канал (по желанию)
1. Создай Telegram-канал, добавь бота администратором.
2. Узнай `chat_id` канала (например, через **@userinfobot** или временно посмотри в логах).
3. Впиши в `.env`: `DIGEST_CHAT_ID=` — и бот будет сам слать дайджест каждое утро.

### Шаг 7. Чтобы работал 24/7 (деплой на Render)
1. Залей проект на **GitHub**.
2. На **render.com** → New → **Blueprint** → выбери репозиторий (там есть `render.yaml`).
3. Впиши секреты (`TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `NCBI_EMAIL`, `DIGEST_CHAT_ID`).
4. Deploy. (Для сохранения базы между перезапусками нужен диск — платный план.)

## ЭТАП 2 — Превратить прототип в настоящий Mini App (позже)

Прототип `miniapp/MNTKMiniApp.jsx` сейчас работает на «заглушечных» данных, чтобы показать
интерфейс. Чтобы он стал боевым Mini App, нужно (это задача для разработчика / Claude Code):

1. **Добавить API к боту.** Обернуть уже готовую логику в HTTP-эндпоинты (FastAPI):
   `/feed`, `/hot`, `/article/{id}`, `/ask`, `/saved`. Данные и поиск у нас уже есть в `src/`.
2. **Собрать фронт.** Создать проект на Vite + React, перенести туда `MNTKMiniApp.jsx`,
   заменить массив-заглушку `ARTICLES` на запросы к API, подключить Telegram WebApp SDK
   (`@twa-dev/sdk`) для темы и авторизации пользователя.
3. **Задеплоить фронт** (Vercel или Render static) и получить https-адрес.
4. **Привязать к боту:** @BotFather → `/mybots` → твой бот → Bot Settings → **Menu Button** →
   вставить адрес Mini App. У бота появится кнопка, открывающая приложение.

Контакт для пользователей (**@codexa_support**) уже стоит на экране «О боте» в прототипе.

## Частые вопросы

- **Бот молчит на вопрос.** Сначала запусти `/digest` — без статей в базе отвечать не на что.
- **Дайджест пустой.** За выбранный период могло не быть новых статей; увеличь
  `DIGEST_LOOKBACK_DAYS` в `.env`.
- **Дорого по токенам.** Уменьши число тем (`SEARCH_TERMS`) и `MAX_RESULTS_PER_TERM`.
- **Русские источники.** CyberLeninka выключена по умолчанию (нестабильный API);
  включается `ENABLE_CYBERLENINKA=true`, при сбое формат полей правится в
  `src/sources/cyberleninka.py`.

## ⚠️ Важно (медицина)
Бот делает обзор литературы, а не назначения. Под каждым ответом — источник и уровень
доказательности. Это инструмент для врача, а не замена клиническому решению.
